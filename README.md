# homelab

GitOps repository for my homelab, built to be **safe to host publicly**.

| Layer | Tool | Where |
|---|---|---|
| VMs on Proxmox | OpenTofu (`bpg/proxmox`) | [`tofu/`](tofu) |
| OS config + Kubernetes install | Ansible (k3s) | [`ansible/`](ansible) |
| Apps & cluster services | Flux | [`kubernetes/`](kubernetes) |
| Secrets | SOPS + age | `*.sops.yaml` everywhere |
| CI | GitHub Actions | [`.github/workflows/`](.github/workflows) |
| Dev environment | DevPod (devcontainer) + mise | [`.devcontainer/`](.devcontainer), [`.mise.toml`](.mise.toml) |
| Dependency updates | Renovate | [`renovate.json`](renovate.json) |

```
.
├── .devcontainer/          DevPod workspace image + post-create setup
├── .github/workflows/      lint (pre-commit + gitleaks history), tofu, kubernetes
├── ansible/                inventory, base playbook, k3s install
├── kubernetes/
│   ├── clusters/homelab/   Flux entrypoint (flux-system/ is generated by bootstrap)
│   ├── infrastructure/     controllers (cert-manager) -> configs (ClusterIssuers)
│   └── apps/               base/<app> + homelab/ overlay
├── scripts/                pre-commit + validation helpers
├── tofu/                   Proxmox VMs for the k3s nodes
├── .mise.toml              pinned tool versions (devcontainer AND CI)
├── .sops.yaml              which files get encrypted, with which keys
└── Taskfile.yml            day-to-day commands (`task --list`)
```

## How it fits together

```
 you ──git push──▶ GitHub ──▶ Actions: lint / validate only (never touches the lab)
                     ▲
                     │ pull (read-only deploy key)
 Proxmox ◀─ tofu ─ DevPod ─ ansible ─▶ k3s VMs ─▶ Flux ──▶ apps
```

* **Flux is pull-based**, so GitHub never needs credentials for, or network access to, the homelab.
* `tofu` and `ansible` run from the DevPod workspace on your LAN. GitHub-hosted runners can't reach
  the lab, and **self-hosted runners on a public repo are dangerous**: a fork PR could run code inside
  your network. Don't add one.

## Secrets

Everything secret lives in files named `*.sops.yaml`, encrypted with [SOPS](https://getsops.io) and
an [age](https://age-encryption.org) key. Only ciphertext is ever committed.

| Secret | File | Consumed by |
|---|---|---|
| Proxmox API token, state passphrase | `tofu/secrets.sops.yaml` | `sops exec-env` → env vars |
| k3s cluster token | `ansible/inventory/group_vars/k3s_cluster/secrets.sops.yaml` | `community.sops` vars plugin |
| App secrets | `kubernetes/**/*.sops.yaml` | Flux `decryption: sops` |
| OpenTofu state | local, gitignored, **also encrypted** | OpenTofu state encryption |

Guard rails that stop plaintext leaking:

1. `gitleaks` on every commit (pre-commit) and over **full history** in CI.
2. `sops-encrypted` hook: any `*.sops.yaml` without SOPS metadata is rejected.
3. `no-plaintext-k8s-secrets` hook: `kind: Secret` outside a `*.sops.yaml` is rejected.
4. `detect-private-key` hook + `.gitignore` for keys, kubeconfigs, state, plans.
5. GitHub secret scanning + push protection (enable it, see below).

The templates (`*.sops.yaml.example`) show the expected keys — copy, fill in, encrypt:

```bash
cp tofu/secrets.sops.yaml.example tofu/secrets.sops.yaml
sops --encrypt --in-place tofu/secrets.sops.yaml
sops tofu/secrets.sops.yaml   # edit later (decrypts in $EDITOR, re-encrypts on save)
```

## Bootstrap

### 0. GitHub repo settings (do this first)

* Settings → Code security: enable **Secret scanning** and **Push protection** (free for public repos).
* Settings → Actions → General: *Require approval for all external contributors*; workflow permissions *Read*.
* Branch protection / ruleset on `main`: require PRs and the `lint` checks.
* Install the [Renovate GitHub app](https://github.com/apps/renovate) for this repo.

### 1. age key (on your host machine, once)

The devcontainer mounts `~/.config/sops/age` from your host read-only, so the key never lives in the repo
or the image.

```bash
mkdir -p ~/.config/sops/age
age-keygen -o ~/.config/sops/age/keys.txt
```

On Windows that folder is `%USERPROFILE%\.config\sops\age\keys.txt`. **Back the key up** (password manager);
losing it means losing every secret. Put the printed public key (`age1…`) into [`.sops.yaml`](.sops.yaml).

### 2. Dev environment

```bash
devpod up github.com/<you>/homelab --ide vscode
```

or `devpod up .` from a local clone. `post-create.sh` installs all tools from `.mise.toml`, the pre-commit
hooks and the Ansible collections. DevPod forwards your SSH agent, which Ansible uses to reach the VMs.

### 3. Proxmox API token

On the Proxmox host:

```bash
pveum role add TofuProvisioner -privs "Datastore.Allocate Datastore.AllocateSpace Datastore.AllocateTemplate Datastore.Audit Pool.Allocate Sys.Audit Sys.Console Sys.Modify SDN.Use VM.Allocate VM.Audit VM.Clone VM.Config.CDROM VM.Config.Cloudinit VM.Config.CPU VM.Config.Disk VM.Config.HWType VM.Config.Memory VM.Config.Network VM.Config.Options VM.Migrate VM.PowerMgmt"
pveum user add tofu@pve
pveum aclmod / -user tofu@pve -role TofuProvisioner
pveum user token add tofu@pve tofu --privsep 0
```

Put the endpoint and token into `tofu/secrets.sops.yaml` (from the example) and encrypt it. Make sure the
`image_datastore` has the **Import** content type enabled (Datacenter → Storage), which needs Proxmox VE 8.4 or later.

### 4. VMs

Edit [`tofu/homelab.auto.tfvars`](tofu/homelab.auto.tfvars) (node name, IPs, your SSH public key), then:

```bash
task tofu:init
task tofu:plan
task tofu:apply
```

### 5. Kubernetes (k3s)

Mirror the IPs in [`ansible/inventory/hosts.yaml`](ansible/inventory/hosts.yaml), create and encrypt the
k3s token secret from its example, then:

```bash
task ansible:site
```

The k3s collection copies a kubeconfig to `~/.kube/` inside the workspace.

### 6. Flux

```bash
export GITHUB_TOKEN=<fine-grained PAT: this repo, Contents + Administration read/write>
task flux:sops-secret
task flux:bootstrap GITHUB_USER=<you>
unset GITHUB_TOKEN
```

The token is used only for bootstrap. Flux keeps a **read-only deploy key**, and you can revoke the PAT
afterwards. From now on, merging to `main` deploys.

## Adding an app

1. Create `kubernetes/apps/base/<app>/` (namespace + HelmRelease or plain manifests + `kustomization.yaml`).
2. Reference it from `kubernetes/apps/homelab/kustomization.yaml`, patching cluster-specific values.
3. Secrets: `kubectl create secret generic x --from-literal=k=v --dry-run=client -o yaml > kubernetes/apps/base/<app>/secret.sops.yaml && sops -e -i kubernetes/apps/base/<app>/secret.sops.yaml`
4. Open a PR, let CI validate it, then merge.

## Pre-commit hooks

| Hook | Why |
|---|---|
| `gitleaks` | secret scanning of staged changes |
| `sops-encrypted`, `no-plaintext-k8s-secrets` | repo-specific secret guard rails |
| `detect-private-key`, `check-added-large-files` | catch keys and accidental binaries |
| `check-yaml`, `check-json`, `yamllint` | syntax and style |
| `end-of-file-fixer`, `trailing-whitespace`, `mixed-line-ending` | keep diffs clean (LF, important when editing from Windows) |
| `check-merge-conflict`, `check-case-conflict` | cross-platform safety |
| `tofu-fmt` | HCL formatting |
| `ansible-lint` | Ansible best practices |
| `shellcheck` | shell script bugs |
| `actionlint` | GitHub Actions workflow errors |

CI runs the same hooks (`pre-commit run --all-files`) with the same tool versions from `.mise.toml`, plus a
full-history gitleaks scan, `tofu validate`, and `kubeconform` on all Kubernetes manifests.

Worth adding later: `commitizen` (conventional commits), `markdownlint`, `trivy config` (IaC
misconfiguration scanning), and `flux-local` (renders and diffs HelmReleases in PRs).
